调用流程

适用于已上传账号的调用方。

1. 获取接入 key

在「上传账号」中提交账号凭据。提交成功后会进入该账号的专属页面，页面中提供接入 key。

2. 请求路由 Cookie

curl -H 'Authorization: Bearer <接入 key>' https://<站点地址>/cookie

返回 JSON，其中 cookie 字段即路由 Cookie。可选参数：gateway=<网关名> 指定网关；force=1 更换为其他网关。

3. 携带 Cookie 请求上游

将 cookie 字段原样放入上游请求的 Cookie 请求头，并在 valid_for_s 秒内使用，到期后重新获取。

完整的返回字段与状态码说明，见账号专属页面的「接入说明」。

对外开放

空闲网关充足时，未上传账号的调用方也可直接获取路由 Cookie。

{{if .PublicOpen}}开放中{{else}}已关闭{{end}}
{{if .PublicOpen}}

当前空闲网关 {{.FreeGateways}} 个，已达到开放门槛（{{.Threshold}} 个），可以不带 key 直接调用：

curl 'https://<站点地址>/cookie?account=<你的 account_id>'
  • account 为必填参数，用于区分调用方，建议填写你的上游账号 ID。
  • 此方式不经过可用性校验，返回的 verified_full 固定为 false。
  • 空闲网关少于 {{.Threshold}} 个时自动关闭，此时请求返回 503。
{{else}}

当前空闲网关 {{.FreeGateways}} 个，未达到开放门槛（{{.Threshold}} 个），暂不接受不带 key 的调用。空闲网关回升到门槛后会自动开放。

上传账号

提交后立即创建账号，并跳转到该账号的专属页面。

凭据类型 仅在粘贴单个 token 时生效；粘贴 JSON 时自动识别

提交须知

  • 系统会定期使用该账号发送探测请求（模型 {{.Model}}，reasoning.effort={{.Effort}}），消耗 0 token，用于发现网关和维护路由 Cookie。
  • 只提供 refresh_token 时，系统会先换取 access_token；未提供 account_id 时，从 token 中自动读取。
  • 提交成功后会跳转到账号专属页面。该页面是查看接入 key、停用账号的入口，请保存好页面地址。
  • 可以随时在专属页面停用账号，停用后系统不再使用该账号发送请求。
{{end}}
