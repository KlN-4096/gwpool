调用流程

适用于已上传账号的调用方。

1. 获取接入 key

在「上传账号」提交凭据，成功后跳转到该账号的页面，接入 key 在那里。

2. 请求路由 Cookie

curl -H 'Authorization: Bearer <接入 key>' https://<站点地址>/cookie

返回 JSON，cookie 字段即路由 Cookie。可选参数：gateway=<网关名> 指定网关；force=1 换一个网关。

3. 携带 Cookie 请求上游

把 cookie 字段原样放进上游请求的 Cookie 头，在 valid_for_s 秒内用完，到期重新取。

完整字段与状态码见账号页的「接入说明」。

当前可用账号 {{.OpenAccounts}} 个，已达门槛（{{.Threshold}} 个），可以不带 key 直接调用：

curl 'https://<站点地址>/cookie?account=<你的 account_id>'
  • account 必填，用于区分调用方，填你的上游账号 ID。
  • 不做可用性校验，verified_full 固定为 false。
  • 只发现成的票，不为你现铸；没有现成票时同样 503。
  • 可用账号少于 {{.Threshold}} 个时自动关闭，请求返回 503。

门槛数的是账号，不是现成的票：一个账号最多摸到 9 个落点，连续供上需要约 {{.Threshold}}×9 个，所以它量的是「池子够不够格」。按现成票数判的话，按需铸票的池子永远开不了。

上传账号

提交后立即创建，并跳转到该账号的页面。

凭据类型 仅在粘贴单个 token 时生效；粘贴 JSON 时自动识别

提交须知

  • 会用这个账号发探测请求（模型 {{.Model}}，reasoning.effort={{.Effort}}），消耗 0 token，用于发现网关和维护路由 Cookie。
  • 只给 refresh_token 时先换 access_token；没给 account_id 时从 token 里读。
  • 提交后跳转到账号页。接入 key 和停用开关都在那里，保存好地址。
  • 可随时在账号页停用，停用后不再用它发请求。
