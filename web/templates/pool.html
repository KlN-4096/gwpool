这是什么

上游不是一台机器，而是一堆网关。同一个账号落到不同网关上，表现可以差很远， 而一个账号在一个网关上的好状态只有第一次接触的那一小段窗口，之后静默失效。 落到哪个网关由两个 cookie（__cflb / __oailb）决定，这里管它叫一张「票」。

池子做的事：用大家托管的账号去各个地区出口试探，把发现的网关攒起来、把票续着， 然后只把刚验过是好状态的票发出去。宁可回 503，也不发一张已经废掉的。

和你用什么客户端无关 —— 你拿到的是一段 Cookie 头， 塞进你自己打上游的那个请求里就行。你的凭据始终是你自己的，池子不碰。

怎么取

curl -H 'Authorization: Bearer <你的 key>' https://<本站>/cookie

key 从哪来：在下面托管一个账号，提交后会给你一个私密页， key 和完整用法（怎么用票、什么时候换、每个错误码什么意思）都在那一页上。 {{if .PublicEnabled}}票富裕时也允许不上传就取，见下一节。{{end}}

端点是上面这个根地址的 /cookie，不是你那个私密页的地址。 把私密页地址当 base URL 拼出来的是 /a/<一长串>/cookie，只会回 404 —— 这是目前为止最常踩的一脚。

票和「好状态」是两层，别混。

一个网关一张票（pair 那一列）。票只是路由，它决定你落到哪台机器上， 和账号无关——任何账号拿同一张票都会落到同一个网关。所以池子每个网关只存一张， 谁来取就借给谁用一会儿（同一时刻只借给一个人：两个账号同时带着同一张票去同一个网关， 这个形状本身就是跨账号共享的特征）。

「好状态」是每个账号自己的。(账号 × 网关) 这个组合叫一个槽位， 每个账号在每个网关上各有一个，各自独立地烧、独立地冷却。所以同一张票， A 用是满血、B 用可能就是降级的——票一样，槽位不一样。

「没碰过它的账号」= 这个网关上，超过 {{.RestedLabel}} 没碰过它、且不在退避期的 托管账号数，也就是大概还有几个人能从这个网关拿到满血。 它只是人眼读数：真实冷却时长至今没测准，所以这个数不参与任何调度决策。

贴进来的凭据只会用来发 ping：模型固定 {{.Model}}、 reasoning.effort={{.Effort}}、只读响应头就断开，累计输出 0 token。 目的只有一个——看你的账号经各个区域出口会落到哪些网关。

提交后你会拿到一个私密查看链接，上面逐条列出我们用你的凭据发过的每一次请求， 另外还有一把 key——上传了凭据就能用这把 key 取池子里的 pair， 这就是池子存在的意义：大家凑出来的网关互相共享。

凭据不加密保存、也不做撤销：不放心的话，在 ChatGPT 的设备列表里取消登录即可失效。
