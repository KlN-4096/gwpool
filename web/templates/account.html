接口说明
客户端自行选择网关、验证品质并维护冷却；原端点仅接受新契约，不保留旧消费调度。

    

      

        
接口位于站点根路径：base URL 是站点地址本身，不是本页地址。把 /a/<页面令牌> 当 base URL 的话，请求会变成 /a/<页面令牌>/cookie，返回 404。

        {{if .BaseURL}}
base URL = {{.BaseURL}}

        {{else}}
base URL = https://<站点地址>（未配置对外地址，找管理员核对）
{{end}}
      


      
1. 请求

      
curl -G -H 'Authorization: Bearer <接入 key>' \
  --data-urlencode 'account=<account_id/user_id>' \
  --data-urlencode 'gateway=unified-142' \
  https://<站点地址>/cookie

      

        
参数说明

        
          
gateway必填。来自目录的网关名称；池子不会替你换网关。

          
account必填。完整成员标识 account_id/user_id，上传者自身与 root Key 也不例外。最大128字节，不可含控制字符。

          
min_remaining可选，接受的最低剩余寿命，30–3600秒；默认300秒。

        
      


      
2. 响应

      
{
  "gateway":          "unified-142",
  "region":           "europe",
  "cookie":           "__cflb=…; __oailb=…",
  "expires_at":       "2026-10-01T12:44:40Z",
  "valid_for_s":      3412,
  "verified_full":    false,
  "ttl_is_advisory":  true,
  "cookie_version":   "…",
  "pair_remaining_s": 3412
}

      

        
字段说明

        
          
gateway本次分配的网关。

          
region铸这张票的出口所属区域，如 us-east、europe。只说明票是从哪儿铸的，不保证你这一发也落在这个区域；池子不知道时没有这个字段。

          
cookie路由 Cookie，原样放入上游请求的 Cookie 请求头。

          
expires_at本次分配的到期时间（UTC）。

          
valid_for_s本次实际有效票的剩余秒数，不是150秒消费窗口，也不证明品质。

          
verified_full固定 false。满血验证由消费端用自己的凭据完成。

          
ttl_is_advisory固定 true：寿命不是品质保证，仍需检查上游响应。

          
cookie_version本次交付 Cookie 的版本摘要，可用 exclude_versions 明确拒收旧票。

          
pair_remaining_s与本次交付同一张有效票的剩余秒数，包含换盆后实际截止，不借用旧库存的期限。

        
      


      
3. 携带 Cookie 请求上游

      
把响应里的 cookie 字段作为 Cookie 头的值：

      
POST https://chatgpt.com/backend-api/codex/responses
Authorization: Bearer <该账号自己的 Codex token>
chatgpt-account-id: <该账号的 account_id>
Cookie: <响应中的 cookie>

      
请求上游时 Authorization 用的是账号自己的 Codex token，不是本服务的接入 key。


      
4. 何时重新获取

      
何时换票与换哪个网关完全由客户端决定：

      
    
        
  • 根据真实凭据期限、品质验证和本地冷却决定是否继续复用。
    • 
        
  • 需要换票时，从新鲜目录选择新网关，再通过 /cookie 明确点名。
    • 
        
  • 不支持 force、wait 或 count；不会现场铸票、批量取票或裸取代选。
    • 
      


      
5. 自己挑网关

      
先取仅含元数据的清单，不批量下载 Cookie：

      
curl -G -H 'Authorization: Bearer <接入 key>' \
  --data-urlencode 'account=<account_id/user_id>' \
  https://<站点地址>/gateways

      
{
  "account": "acct-…",   // 回显这份清单是按谁算的
  "live":    4,          // 现在有几个网关有活票
  "target":  6,          // 池子想维持的深度
  "gateways": [
    { "name": "unified-167",
      "pair_ready":   true,
      "valid_for_s":  2400 }
  ]
}

      
结合本地冷却和品质记录选择候选。目录不含 used_by_you 或 last_used_at。
      Sub2api 按身份/Key/模型隔离短时目录缓存，最多30秒；点名缺票或候选耗尽时刷新。刷新失败表示未知库存，不是耗尽。


      
6. 一把 key 给好几个账号用

      
每次都必须带实际消费成员的完整标识。同一成员跨 Key 共享滚动限频：
      每1秒12次、每60秒444次；成功与缺票都计数，鉴权失败不占成员额度。
      清单和报告不占取票额度；公共 Key 与独立 Key 的额外访问限制仍有效。

      

        
外部统计只用于观察，不决定交付资格、冷却或排序，也没有历史消费者数量准入上限。
        /cookie 和 /gateways 直接执行新契约，缺参或携带退役参数时400提示升级；
        /release、/pair/renew 仅返回停用/升级错误。

      


      
7. 状态码

      

        
状态码含义处理建议

        
          
200成功，返回路由 Cookie。按第 3 步携带 Cookie 请求上游。

          
400参数不合法，例如 gateway 取值有误。网关名只能包含字母、数字、-、_、.。

          
401缺少接入 key，或 key 无效。检查 Authorization 请求头；账号停用期间 key 不可用。

          
426消费者归还/续期接口已停用。升级至最新版 Sub2api，使用原路径下的新契约。

          
429consumer_rate_limited，成员取票超限。遵守 Retry-After，不换 Key 绕过成员限频。

          
503指定网关缺有效票，或公共接入未开放。按错误码处理；缺票时刷新目录，由客户端重新选择。

        
      

      
缺票不是满血耗尽的证据。只在新鲜目录成功返回后，由客户端根据本地状态判断是否耗尽。
