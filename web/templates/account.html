接口说明
先通过 /cookie 获取路由 Cookie，再携带它向上游发起请求。

    

      

        
接口位于站点根路径：base URL 是站点地址本身，不是本页地址。把 /a/<页面令牌> 当作 base URL 时，请求会变成 /a/<页面令牌>/cookie 并返回 404。

        
base URL = https://<站点地址>

      


      
1. 请求

      
curl -H 'Authorization: Bearer <接入 key>' https://<站点地址>/cookie

      

        
参数说明

        
          
gateway可选。指定网关名称，例如 unified-142；不指定时由系统选择。

          
force可选。设为 1 时跳过你当前正在使用的网关，改为分配其他网关。

        
      


      
2. 响应

      
{
  "gateway":         "unified-142",
  "cookie":          "__cflb=…; __oailb=…",
  "expires_at":      "2026-10-01T12:44:40Z",
  "valid_for_s":     150,
  "verified_full":   true,
  "ttl_is_advisory": true
}

      

        
字段说明

        
          
gateway本次分配的网关。

          
cookie路由 Cookie，原样放入上游请求的 Cookie 请求头。

          
expires_at本次分配的到期时间（UTC）。

          
valid_for_s本次分配的建议使用时长，单位为秒，到期后请重新获取。

          
verified_full分配前是否已对该网关完成可用性校验。

          
ttl_is_advisory固定为 true，表示有效期只是建议值，实际以上游响应为准。

        
      


      
3. 携带 Cookie 请求上游

      
将响应中的 cookie 字段作为请求头 Cookie 的值：

      
POST https://chatgpt.com/backend-api/codex/responses
Authorization: Bearer <该账号自己的 Codex token>
chatgpt-account-id: <该账号的 account_id>
Cookie: <响应中的 cookie>

      
注意：请求上游时 Authorization 使用的是账号自己的 Codex token，不是本服务的接入 key。


      
4. 何时重新获取

      
路由 Cookie 按「账号 × 网关」分配，出现以下情况时重新调用 /cookie：

      
    
        
  • 距上次获取已超过 valid_for_s 秒。
    • 
        
  • 当前网关不可用、需要换一个网关时，加上 force=1：
          
    curl -H 'Authorization: Bearer <接入 key>' 'https://<站点地址>/cookie?force=1'
    • 
        
  • 需要固定使用某个网关时，传入 gateway 参数，例如 /cookie?gateway=unified-142。
    • 
      


      
5. 自己挑网关

      
不想让池子替你挑，就先要一份清单：

      
curl -H 'Authorization: Bearer <接入 key>' https://<站点地址>/gateways

      
{
  "account": "acct-…",   // 回显这份清单是按谁算的
  "live":    4,          // 现在有几个网关有活票
  "target":  6,          // 池子想维持的深度
  "gateways": [
    { "name": "unified-167",
      "pair_ready":   true,     // 有活票；false 的话你指定它池子得现铸，会慢
      "valid_for_s":  2400,
      "used_by_you":  false,    // ← 你在这个网关上烧过没。挑 false 的
      "last_used_at": "2026-10-01T12:00:00Z" }
  ]
}

      
挑一个 pair_ready=true 且 used_by_you=false 的，然后
      /cookie?gateway=<挑中的>。


      
6. 一把 key 给好几个账号用

      
这把 key 不止能给上传的那个号取票。你手上别的 Codex 账号也能用它，但必须说清这一发
      是给谁的——每次都带上那个账号自己的 account_id（就是它 token 里的
      chatgpt_account_id）：

      
curl -H 'Authorization: Bearer <接入 key>' 'https://<站点地址>/cookie?account=<那个号的 account_id>'
curl -H 'Authorization: Bearer <接入 key>' 'https://<站点地址>/gateways?account=<那个号的 account_id>'

      
不带的话池子会把这次使用记在上传者头上，于是它以为那个网关已经
      被用过了——白白划掉一个对你这个号其实还是满血的落点。满血是 (账号 × 网关) 的：A 号烧掉
      unified-167 和 B 号在 unified-167 上是不是满血，毫无关系。

      

        
这种票回的 verified_full 是 false，别理解成「这张票可能是坏的」。

        
它的意思是池子答不了这个问题：验满血要用那个账号自己的凭据打一发，
        池子手上只有上传者的。拿上传者的凭据去验，答的是上传者的状态，对你这个号没有信息量。

        
票本身没问题——cookie 只是路由，谁铸的都一样，连降智的号铸出来的也一样好。
        你这个号是不是满血，只取决于你自己碰过这个网关没，而那个答案在
        /gateways 的 used_by_you 里。

      


      
7. 状态码

      

        
状态码含义处理建议

        
          
200成功，返回路由 Cookie。按第 3 步携带 Cookie 请求上游。

          
400参数不合法，例如 gateway 取值有误。网关名只能包含字母、数字、-、_、.。

          
401缺少接入 key，或 key 无效。检查 Authorization 请求头；账号停用期间 key 不可用。

          
404请求地址错误。确认请求的是站点根路径下的 /cookie，而不是本页地址下的路径。

          
503暂时没有可分配的路由 Cookie。稍后重试；系统已自动安排为该账号探测新的网关。

        
      

      
503 不代表服务故障：它表示当前可分配的网关已全部占用，稍后重试即可。
