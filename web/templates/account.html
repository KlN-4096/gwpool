怎么用

  
池子只做一件事：给你一张路由 cookie。你拿它去打你自己的
  Codex 请求，上游就会把你落到那张票对应的网关上。和你用什么客户端无关。


  

    
端点是站点根地址的 /cookie，不是本页地址。

    
本页地址（/a/<一长串>）是你的凭证页，不是 API。把它当 base URL
    拼出来的是 /a/<一长串>/cookie，只会回 404。

    
base URL = https://<本站>　←　到域名为止，后面什么都不带

  


  
一、取票

  
curl -H 'Authorization: Bearer <你的 key>' https://<本站>/cookie

  
回的是 JSON：

  
{
  "gateway":       "unified-142",   // 落到哪个网关，自己记日志用
  "cookie":        "__cflb=…; __oailb=…",  // ← 整段原样放进请求头
  "expires_at":    "2026-10-01T12:44:40Z", // 这张票的硬过期，上游定死 65 分钟
  "valid_for_s":   150,             // 建议用多久，**不是承诺**
  "verified_full": true,            // 池子刚验过它是满血的
  "ttl_is_advisory": true
}


  
二、用票

  
把 cookie 整段塞进你发给上游的 Cookie 请求头，别的什么都不用改：

  
POST https://chatgpt.com/backend-api/codex/responses
Authorization: Bearer <你自己的 Codex token>
chatgpt-account-id: <你自己的账号 id>
Cookie: <上面那段 cookie 原样>

  
同一轮对话里一直用同一张：换票等于换网关，上下文缓存和
  路由都会跟着变。票不是你的凭据，它只决定你落到哪台机器上——你的 token 还是你自己的。


  
三、什么时候换

  
满血是 (账号 × 网关) 第一次接触的那一小段窗口，之后静默失效——
  上游不会告诉你它失效了，响应里一个字都不会变。所以：

  
    
    
  • 拿到就用，别缓存、别预取。valid_for_s 过了就当它废了。
    • 
    
  • 觉得这一发不对劲了，要一个不同的网关：
      
    curl -H 'Authorization: Bearer <你的 key>' 'https://<本站>/cookie?force=1'
    
      它不会把刚给过你的那张再发一遍；实在换不出别的就回 503。
    • 
    
  • 想回到某个特定网关：/cookie?gateway=unified-142。
    • 
  

  
什么时候该换由你判断，池子不替你猜。也不用回报用完了——
  票是池子发的、满血也是池子验的，你知道的它都知道。


  
四、回什么错就是什么意思

  

    
状态意思该怎么办

    
      
200给你一张票立刻用

      
401key 不对，或者这个账号被停用了
        对一下上面那把 key；本页顶上显示「已停用」就是被停了

      
503此刻没有验过满血的票
        等一两分钟再来，别重试打。池子宁可 503，也不把降级的票发给你。
          回了 503 说明你的号在已知网关上都烧过了，池子会同时派别的托管账号去找新网关
          （一次约一分钟），新落点上你才是首次接触

      
400参数不对（比如 gateway= 填了个不存在的）
        看回的那句话

      
404你把本页地址当成了 base URL见上面那个框

    
  

  
503 不要快重试。每一次取票请求都会让池子真打一发上游去验满血，
  空转就是在烧大家共用的供给——包括你自己的号。
