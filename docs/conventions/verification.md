# 验证与部署

- Go 标准库项目；入口为 `cmd/gwpool`，模板由 `web` 嵌入。
- 测试用 fake/httptest，不能请求真实上游；非平凡 bug 先添加能失败的回归用例。
- 上传页面解析与部分成功/重试用 `node --test web/upload_parser.test.cjs` 离线验证；`web/testdata/sub2api-export.json` 是假凭据契约样本，不是真实账号验收。
- 重登用`internal/reauth`假传输、`httpapi/upload_jobs_test.go`真Store任务测试；`GWPOOL_UPLOAD_PREVIEW_DIR`+`TestUploadWorkspaceFixture`导出假页面。opt-in `reauth_probe`标签单账号探针仅显式授权后运行，配置stdin、账号文件按行读取，输出固定阶段/失败码，不保存Token或写池；遇人机挑战停止。
- 管理页分组/旧锚点/历史导航用 `node --test web/navigation.test.cjs`；无JS仍展示所有分区。
- Key管理回归：`store/access_key_test.go`、`httpapi/managed_keys_test.go`、`node --test web/keys.test.cjs`；`GWPOOL_KEYS_PREVIEW_DIR`从离线测试输出列表/生成/详情假数据页面，禁止用生产Key做UI截图。
- `TestDashboardSettingsFixture`可通过`GWPOOL_PREVIEW_DIR`输出假数据HTML供本地静态预览；不要用生产凭据做截图或表单测试。
- Windows 原生 Go 构建和测试；并发限定 `-p 2`，测试使用 `-timeout 60s`，不跑 `-race`。
- 小改先跑定向用例；涉及共享铸票/调度行为时运行 `go test -p 2 -timeout 60s ./...`，再 lint。
- `tools/benchmark.ps1`使用远端先失效化凭据的真实快照，真实Store/Scheduler/HTTP、原生子进程隔离服务端与压测堆；每场记录全源码hash、同32消费者/非空tag、每响应校验与性能断言。CPU/IO只计server，Windows IO含控制管道，不称物理磁盘量；结果与线上/旧轻负载基线不能拼接。
- 2026-10-05本地N1024每场验收：GET P95 9.006ms，single P95/P99 24.763/62.630ms，batch3 42.056/83.011ms。只适用于充足库存/本地回环，不承诺缺票、外网或模型验证延迟；线上2vCPU另列实测。
- Linux 产物采用 `GOOS=linux GOARCH=amd64 CGO_ENABLED=0`，`-trimpath -ldflags="-s -w"`。
- bytevirt 的服务和二进制是 `gwpool`、`/opt/gwpool/gwpool`；配置在 `/opt/gwpool/data/config.json`。
- 切换前比对旧二进制 SHA256，保留回滚文件，避免覆盖其他会话的部署。
- 旧部署备份/上传包/预演目录经用户明确清理授权后才处理，且先完成新版本验收；优先trash-put，不把移入回收站算成释放磁盘。正式config/state、自动每日快照与未确认用途的实验材料不当部署残留。
- 上线验收同时看服务健康、自然续票的真实成功/失败、预铸补货和 TTL；仅“测试绿/进程 active”不算业务验收。
- 开启site_key时匿名根页403是正常门禁；基线/恢复鉴权检查从既有配置读取gwp_gate Cookie，不把密钥放URL或输出。短观察窗未确认200不等于服务未启动，先核PID/生命周期并独立复查，不能据此重复重启。
- `routing_experiment`标签研究不进入正式构建；原Store只在原进程退出时独占，尝试不退款。接触journal须在请求前落盘，且请求绝对deadline在journal Sync之前建立；恢复重放只幂等推进原有touch，不发布未经后验的路线。
- 路由预测研究先冻结数据/源码/参数/时间与停止规则，再一次揭盲；成功条件命中率须并列失败分母、身份重复和端点重叠。已揭盲标签只能作后续开发材料，不能重复当独立验证。
- `__oailb.host`是可见票声明，state-echo的Full是头部启发式，两者都不是独立compute/model能力遥测；不得用cookie TTL推品质期，或用同源echo循环证明“满血”。
