# 多来源恢复与有界新身份探索

- 授权：2026-10-14 用户“做吧”；首轮本地实现/验证，不含推送部署，不改429冷却、总配额、并发和消费协议。
- 验收：A→B漂移不遗忘A的其它真实来源；无来源/历史未补齐时，周期维护可限额试新身份；命中才成为新来源，副落点不冒充目标恢复；需求唤醒不增加探索机会。
- 证据：194无当前候选且最后票来源已删；176候选只剩116×KH；128正常实例1h退避有效，5.41min重试跨过部署重启。
- 方案：独立有界持久裸铸来源索引（保存真实身份/地区/source/原观察时间，不从旧Pair补造）；旧路线可迁入仍可信的一条映射。新身份探索在原12任务轮次剩余额度内、普通维护完成后低频单任务执行，目标轮换、身份去重、旧预算/路线锁不变。
- 已完成本地实现：两个最小回归先红后绿；全量Go（-p 2 -timeout 60s）通过；两轮独立对抗审查的provider选择与短票误报问题已复现修复，无剩余blocker/should-fix。针对性lint被旧工具的Go1.27导出格式兼容性阻断。
- 有界语义：来源7天/全局4096/每网关16；普通维护之后、原12任务余量内每15分钟单任务，目标轮转，身份去重/24h重检；机会与尝试缓存进程内，重启仅从保留的LastTarget恢复部分排除，原持久配额不变。
- 边界：旧完整samples不全量回放或冒充身份/source；没有历史出口不猜机房所在地；旧来源过期/换身份/停用不成为现时证明。
- 发布注意：新增持久字段后需新旧独立副本严格重放与新schema回滚守卫，不能用旧binary“能启动”当成兼容证明。
