# 铸票路径核对（2026-10-03，进行中）

## 本轮已定位并修复，已部署 0722f41

- 续票从 `ReachableExits` 随机取区域，但 cookie 来自 `Pair.RegionKey`；速率桶、样本与新票标签可能串区。改为票据区域的标准参数，种子路由不要求住宅历史出口。
- 续票把单账号区域限流当成全池故障；排头限流导致后续账号整轮饿死。改为预检后跳过，并处理预检到出手之间的限流竞态。
- 原日志 `done` 同时计入成功与失败；改为 attempted / renewed / failed / throttled，逐次成功另报剩余 TTL。
- 05:24 UTC 八分钟窗口：自然续票成功 6、漂移 3，末轮 4/4 成功；原始可交付 94/106，仍有一组 cflb 跨区域标签冲突。不能把存量/上游漂移说成全部修复。

## 待核对/暂不扩大本轮修复

- `scan.Scanner.attempt` 与 `sched.mintOnce` 是两套落账路径。前者直接记请求区域及 `ReachableExits`；后者有住宅出口国家不符的过滤、种子例外和新票换盆。全量打票不能再复制第三套。
- `sched.mintOnce` 在 `Mint` 返回 error 后先退出，再处理 HTTP 状态；`scan` 已对“有响应状态但解析 cookie 失败”先分状态。需补 401/429 + 无新 `__oailb` 的离线用例核实差异。
- 活 cflb 的“同区”依赖历史 RegionKey。12:46 台北的只读快照中，同一 cflb 存在 2 组跨区域标签，不能仅修新写入后就声称旧数据全部可靠。
- `premintNote` 的 got 是补货计数；仍需核对响应新票是否真的达到交付门槛，以及多 worker 同轮相撞的计数。
- 内存速率窗口重启清零。频繁部署会放宽当小时的实际预算，本轮不提高配额或并发，避免不必要重启。
- `SPEC.md` 的旧“池子不续期”与恢复后的 `renew_pairs` 冲突；个别注释把区域×账号映射写成绝对保证，而 `types.RegionMint` 明确只把它当预测。
